# 完全离线与内网部署要求

更新日期：2026-09-22。本文定义产品目标和发布验收条件；不是已完成断网验收或涉密环境认证的声明。

## 核心定位

AutoMaticWorker 是以完全离线运行为核心的开源自动化平台与 SDK，面向内网和涉密环境的本地部署需求。数据、流程、配置、日志与执行结果保留在部署环境内。开发者掌握基础 Python、简单的 Playwright 定位与页面操作，配合 SDK 即可制作标准流程包；平台承担环境、配置、运行、日志、取消及交付管理。

平台和通用 SDK 开源，具体业务流程独立交付，商业模式为付费制作、部署适配及维护。离线运行不依赖平台账号、云端服务或在线许可证校验。

## “完全离线”的含义

| 部署场景 | 允许的通信 | 必须成立的条件 |
| --- | --- | --- |
| 单机断网 | 本机文件及回环地址 | 无外部网络也能安装、首次启动、导入、执行、查看结果和更新；涉及网页时使用本机页面 |
| 隔离内网 | 本机及客户指定的内网业务系统 | 无公网出口也可完成流程；内网 DNS、证书和业务登录按部署环境提供 |

本地 UI 使用 `127.0.0.1` HTTP 服务，属于进程间本机通信。断开网卡不会让公网业务网站变为可访问，也不应把“完全离线”解释为禁止必要的本机回环通信。内网流程依赖其业务系统可用，但不能借此要求公网下载、认证、授时或模型服务。

## 运行与数据原则

- 平台、SDK 及默认模板不引入公网账号登录、在线激活、周期性授权检查、云模型调用或公网时间服务器依赖。
- 不内置遥测、分析、远程错误上报、自动更新检查和运行时依赖下载。版本升级由本地导入离线更新包完成；补丁与回滚同样离线交付。
- UI 的脚本、样式、字体、图标和帮助材料随包提供，不从 CDN 或在线文档加载必需资源。
- 浏览器配置、登录目录、输入文件、日志、截图和结果留在本地；导出操作由用户发起。SDK 不自行同步数据到外部服务。
- 流程包只访问其部署场景指定的本地或内网资源，缺少组件时给出本地诊断，不隐式访问包源补装。
- 平台运行不依赖 AI。AI 制作是可选开发方式；隔离环境可以人工开发或使用该环境允许的本地模型。公开 Skill 与模板可离线读取，不能把“使用 Skill”变成连接外部 AI 的前置条件。
- 公网开发环境只使用公开代码和合成样例；客户内部页面、代码、凭据与数据的处理按其部署环境要求执行，不作为默认远程调试材料。

这些是平台设计约束，不是网络沙箱。当前导入的 Python 包具有本机用户权限；浏览器、WebView2、第三方依赖和操作系统也可能产生后台网络行为。禁止外联的环境需结合主机或网络出口策略，并通过观测验证；单靠静态代码搜索或浏览器拦截器不能证明整个进程树没有外联。

## 离线交付物

发布环境与用户运行环境分离。开发侧可在允许联网的构建环境准备公开依赖，随后交付可校验的完整本地材料；用户机器不需要临时联网。

| 组件 | 交付要求 |
| --- | --- |
| 平台 | Windows 可安装包或完整离线分发目录，含运行时及构建好的前端；终端用户不需要运行 npm |
| Python 与依赖 | 按操作系统、架构、Python 版本锁定；附可离线安装的依赖或打包运行时，不能只附 requirements 文本 |
| Playwright | 对应 Python 包、其驱动运行资源及匹配的浏览器二进制一起准备；选择本地路径，缺失时报错，不在线下载 |
| Patchright / 桌面输入 | 可选模块单独提供同版本离线依赖与验证记录，不能成为标准后端必装组件 |
| WebView2 | 离线安装材料，或经桌面集成验证的固定版本运行时；不能用仅能联网下载的引导器充当离线安装包 |
| 文档与 Skill | 完整本地引用、示例和制作工具；外部资料链接仅供开发参考，运行与制作基本流程不依赖打开外链 |
| 清单与升级 | 文件哈希、依赖版本、许可证、适用系统和本地升级/回滚说明；校验通过不等于已获得涉密使用资质 |

[Playwright 官方说明](https://playwright.dev/python/docs/browsers)指出其版本需要相应浏览器二进制，默认安装会下载资源；因此“pip 包装好了”不等于离线浏览器环境齐全。[WebView2 分发说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)区分在线引导、离线安装与固定版本方案；最终组合须在本项目桌面封装中验证。

## 开发者最小学习路径

1. 基础 Python：变量、函数、循环与异常。
2. 简单 Playwright：页面导航、语义定位器、iframe/标签页及结果条件。
3. SDK：复用浏览器会话、点击与输入、日志进度、取消和结果输出；复杂交互通过 SDK 统一实现。
4. 流程包：声明参数和环境需求，实现入口，运行本地验证，打包 ZIP 后导入平台。

不要求流程作者学习 Flask、Vue、桌面进程管理或自行维护浏览器安装器。SDK 保持贴近 Playwright 的页面与 Locator 模型，避免新增一套复杂的自定义脚本语言。保留原生 API 出口，同时明确所需后端。

当前已实现第 4 项的基础契约以及部分运行上下文；第 3 项的浏览器交互 SDK 属于 M2.1。不能向 v0.2 流程包导入尚未实现的设计 API。

## 断网验收矩阵

所有项目目前均为待执行的专项验收，不能把既有 M2 功能测试记录为以下测试已通过。

| 场景 | 证据要求 |
| --- | --- |
| 无公网、无包缓存的干净 Windows | 从完整交付物安装、首次启动，不触发下载；记录系统和组件版本 |
| 单机断网 | 导入报告包和本地网页包，配置、运行、取消、结果导出完整通过；回环服务正常 |
| 仅内网可达 | 访问指定内网测试站，完成人工登录、浏览器流程、异常及重试边界验证 |
| 外联观测 | 覆盖安装、首次启动、空闲、登录、运行、异常、关闭和更新；检查平台及子进程的 DNS/连接尝试，区分访问被阻断与没有发起请求 |
| 依赖缺失 | 移走测试环境的浏览器或可选依赖后，显示明确本地错误，不自动下载 |
| 离线升级 | 导入本地升级材料，验证旧包兼容、数据保留及回滚，不访问在线许可证和更新服务 |
| 可选 AI 制作 | 本地材料可完成手工制作；选用本地 AI 时另行验证该模型环境，不作为普通执行的依赖 |

通过条件：约定工作流在无公网环境完成，全部必需材料来自离线交付物；平台及受控组件无未解释的公网请求，证据记录可复核。涉密环境的准入、部署策略和现场验收按使用单位要求执行，项目目前不声明取得相应认证。
